# 006 — Chatbot Admin Dashboard requirements

Status: Application implementation explicitly approved by the user on 2026-10-10. Production release and overall acceptance remain pending. See [implementation evidence](evidence/application.md).

## Scope and inspected baseline

Provide authenticated web management of prepared FAQs and retained visitor questions in the existing Laravel application. Feature [005](../005-chatbot-question-collection-faq/design.md) remains authoritative for matching, original classification, public response/replay, retention and restricted console operations.

Repository inspection on 2026-10-09 found Laravel `^13.17`, Vue 3/TypeScript, Tailwind and existing Vite/Vitest tooling. Feature 005 models, migrations, `FaqNormalizer`, `FaqService`, question API, restricted Artisan commands, retention and dedicated test infrastructure exist in the working tree. `FaqService` implements create/update/activation/revisions but has no deletion method. The existing `web` session guard and `User` model are available; there are no login screens, admin routes, admin role fields or policies. No authentication starter package is installed. Do not assume an existing login experience or production deployment of these files.

Feature 005 records passing automated revalidation (41 PHPUnit tests/304 assertions, 49 Vitest tests, typecheck/build/Pint); these are historical records, not tests run for this specification. Its missing historical baseline and manual/production/privacy gates remain pending. Recheck the implementation before starting 006; if its schema/services are absent from the target checkout, stop at the dependency gate rather than duplicate them.

## Approved application product decisions

1. A single chatbot-admin capability grants FAQ management and restricted question deletion; deletion additionally requires a password confirmed within 15 minutes. More granular roles are deferred.
2. Build minimal session login and operator-only account create/grant/revoke/password-reset workflows using existing Laravel facilities. Public registration, browser account management, email recovery, SSO and MFA are outside this feature; the security owner must approve this authentication scope before production release.
3. Admin sessions expire after 30 minutes idle or 8 hours absolute. Login allows 5 attempts per account and 20 per client IP per 60-second window; authenticated administration allows 120 requests per admin per 60 seconds. These are independent of 005 quotas.
4. Search is case-insensitive, accent-sensitive literal substring search; default page size 25, optional 50, stable cursor navigation. Do not add a mutable “resolved” state or historical metrics.
5. Selected-question deletion requires protected restoration instructions for the 30-day backup lifetime. The deployment/privacy owners must approve the durable storage and restore runbook; app tests cannot establish backup erasure or production readiness.

The user approved all four documents and these application decisions on 2026-10-10. Any change to these choices requires revised specification approval; production security/privacy gates remain separate.
